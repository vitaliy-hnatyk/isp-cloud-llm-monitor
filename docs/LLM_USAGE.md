# How to use the monitor with LLM APIs

Use this guide to test **API availability and response timing**, not model quality. All commands run from the project directory with Python 3.9+.

## 1. Preview the dashboard with no keys

```bash
python provider_monitor.py --all-tests --llm-all-providers --demo --output demo_report.html
```

Open `demo_report.html` in your browser. All values are simulated.

## 2. Configure API keys locally

Copy `api_keys.env.example` to `api_keys.env` and replace the placeholder values with genuine secrets from each provider's developer console. `api_keys.env` is in `.gitignore`.

Windows PowerShell:

```powershell
Copy-Item api_keys.env.example api_keys.env
notepad api_keys.env
```

Linux/macOS:

```bash
cp api_keys.env.example api_keys.env
# Edit locally; do not publish the file.
```

No key values are embedded in example commands or stored in HTML/CSV reports. The `model_index.json` generated by the optional model indexer may disclose your available model IDs, so it is ignored by Git as well.

## 3. Check each LLM service without inference

These commands call authenticated `GET /models` and do not generate text:

```bash
python provider_monitor.py --no-default-targets --llm-provider openai --llm-mode models --env-file api_keys.env --minutes 2 --interval 30
python provider_monitor.py --no-default-targets --llm-provider anthropic --llm-mode models --env-file api_keys.env --minutes 2 --interval 30
python provider_monitor.py --no-default-targets --llm-provider kimi --llm-mode models --env-file api_keys.env --minutes 2 --interval 30
python provider_monitor.py --no-default-targets --llm-provider mistral --llm-mode models --env-file api_keys.env --minutes 2 --interval 30
```

Or test them together:

```bash
python provider_monitor.py --no-default-targets --llm-all-providers --llm-mode models --env-file api_keys.env --minutes 5 --interval 60 --llm-timeout 15
```

Missing credentials are reported before a live run. Run `python provider_monitor.py --list-llm-providers` to check the supported preset names and API key environment variables.

## 4. Include ISP, DNS, AWS and Azure in the same run

```bash
python provider_monitor.py --all-tests --llm-all-providers --llm-mode models --env-file api_keys.env --minutes 10 --interval 60 --llm-timeout 15
```

This generates `provider_report.html` and `provider_report.csv`. Measurements are sequential and timeouts can cause an iteration to last longer than `--interval`.

## 5. Run a small generation test (may be billed)

Select an actual model ID available in your account. Use `scripts/fetch_model_index.py` to list available model IDs, or consult your provider dashboard.

For an Anthropic Messages API test:

```bash
python provider_monitor.py --no-default-targets --llm-provider anthropic --llm-mode chat --anthropic-model YOUR_ANTHROPIC_MODEL_ID --env-file api_keys.env --minutes 1 --interval 30
```

For a Kimi chat API test:

```bash
python provider_monitor.py --no-default-targets --llm-provider kimi --llm-mode chat --kimi-model YOUR_KIMI_MODEL_ID --env-file api_keys.env --minutes 1 --interval 30
```

For a Mistral chat API test:

```bash
python provider_monitor.py --no-default-targets --llm-provider mistral --llm-mode chat --mistral-model YOUR_MISTRAL_MODEL_ID --env-file api_keys.env --minutes 1 --interval 30
```

For an OpenAI Responses API test:

```bash
python provider_monitor.py --no-default-targets --llm-provider openai --llm-mode responses --openai-model YOUR_OPENAI_MODEL_ID --env-file api_keys.env --minutes 1 --interval 30
```

To run all four in chat mode, supply all four model flags (`--openai-model`, `--anthropic-model`, `--kimi-model`, and `--mistral-model`). The monitor uses a short "Reply with OK" prompt and collects only timing, status and selected token-count metadata, not the generated text. Paid inference might incur usage charges. Avoid long-duration frequent inference probes.

## 6. Test an OpenAI-compatible local server

For a local server implementing `/v1/models` (e.g. a compatible gateway running on your machine):

```bash
python provider_monitor.py --no-default-targets --llm-base-url http://localhost:11434/v1 --llm-mode models --minutes 2 --interval 20
```

For chat generation, add `--llm-mode chat --llm-model YOUR_LOCAL_MODEL`. Remote HTTP is not allowed when an API key is configured: use HTTPS for external authenticated endpoints.

## 7. Build a model index and read the HTML report

```bash
python scripts/fetch_model_index.py --provider openai --env-file api_keys.env
```

The generated `model_index.json` lists model IDs and names; the HTML report instead summarizes **probe success/latency over time**. The list of models available to your account can change and may be paginated.

## Interpreting failures

| Result | Likely areas to investigate |
|---|---|
| HTTP 401 / 403 | Key invalid, missing permissions, wrong workspace or billing access |
| HTTP 404 | Incorrect endpoint or unavailable model ID |
| HTTP 429 | Quota or rate-limit reached |
| Timeout / connection error | DNS, network routing, blocked connection or remote service |
| High response time | Network + TLS + remote application/model time; not comparable directly with TCP ping |

An API failure does **not** by itself prove an ISP outage. Compare with independent TCP/DNS/HTTPS results and, where possible, test using wired Ethernet.
